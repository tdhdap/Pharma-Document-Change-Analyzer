# DOCX/PDF Test Document Generation Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Generate 20 real DOCX/PDF fixture files (5 scenarios × 2 versions × 2 formats) that translate the existing `test-documents/*.txt` scenarios into real binary documents, each scenario deliberately using one heading-detection convention so the fixtures double as isolation tests for the multi-signal heading detection built in `docs/superpowers/plans/2026-07-31-multi-signal-heading-detection.md`.

**Architecture:** One script, `scripts/generate_test_documents.py`, holds all scenario content as Python data plus two generic writer functions (`write_docx`, `write_pdf`) that apply a named heading convention (`structural`, `all_caps`, `mixed`, `font_size`, `none`). A `validate()` helper runs each generated file through the real backend pipeline (`extract_text` → `split_into_sections`) and asserts the resulting heading sequence is exactly what's expected — this is the test oracle for this plan, replacing pytest's red/green cycle since there's no application code under test, only generated fixture content. Each task adds one scenario's data, extends `main()` to generate+validate it, and commits.

**Tech Stack:** `python-docx`, `PyMuPDF` (`fitz`) — both already installed and used by `backend/app/extraction.py`. No new dependencies.

## Global Constraints

- No new dependencies — only `python-docx` and `fitz`, already installed.
- Reuse the exact section text/content from the existing TXT scenarios unchanged, with two documented exceptions: (1) SOP v2's PDF fixture gets one extra trailing body-only sentence not present in `SOP_v2.txt`, added solely to break an exact block-count tie in the PDF font-size baseline computation (see Task 4 — verified empirically while writing this plan); (2) C1's "Analytical Results Table" body line is reworded from the real source's "10.5 | 20.3 | conforms" to "Result: 10.5, 20.3, conforms" (see Task 3), because the original text matches the pre-existing, already-shipped `HEADING_NUMBER_PATTERN` regex and would be spuriously split into its own heading — verified reproducible against the real, unmodified `C1_v1.txt` too, so this is a pre-existing latent behavior of already-reviewed code, not a defect this plan introduces or should fix.
- Each scenario is assigned exactly one heading-detection convention to isolate (per the approved spec), and each scenario's heading text must contain nothing that could ALSO satisfy a different signal — this is what makes a scenario an isolation test rather than merely a heading-detection demo. Concretely: **A** → structural only (Word style / PDF TOC) — numbering prefix stripped from heading text (matching B/SOP's approach) so the pre-existing numbered-pattern signal cannot also catch these headings; without this, deleting the structural-signal code entirely would leave A's validation passing, which would prove nothing. **B** → ALL-CAPS only, numbering prefix stripped. **C1** → mixed (alternating structural / plain-numbered-text-only) — numbering is intentionally kept here (unlike A/B/SOP) because this scenario exists to test the *swallowing-bug fix*, not signal isolation: every heading's text matching the numbered pattern is what makes the alternation meaningful (see Task 3's brief for the full reasoning). **C2** → none (no headings at all — preserves the original TXT scenario's actual structure, which has zero headings). **SOP** → font-size only, numbering prefix stripped.
- Output files land in `test-documents/docx/` and `test-documents/pdf/`, named `<Scenario>_<version>.<ext>` (e.g. `A_v1.docx`, `SOP_v2.pdf`).
- The generator script must be idempotent — re-running it regenerates/overwrites all 20 files from the same data, no manual cleanup required.
- Validation (via the real `extract_text` + `split_into_sections` pipeline) runs as part of each task's own script execution, not as a separate later step — a task isn't done until its own scenario's 4 files pass validation.
- `write_docx` and `write_pdf` are built complete (all 5 convention branches) in Task 1, since they're generic shared infrastructure — later tasks only add scenario data and `main()` calls, they do not modify the writer functions. A branch that isn't exercised until a later task (e.g. `font_size` isn't used until Task 4) is intentional, not dead code — say so if reviewing Task 1 in isolation.

```python
"""Generate DOCX/PDF test fixtures for the doc-change-analyzer's 5 existing
TXT scenarios (A, B, C1, C2, SOP). Each scenario is assigned one
heading-detection convention (structural / all_caps / mixed / font_size /
none) so the fixtures double as isolation tests for the multi-signal
heading detection built in
docs/superpowers/plans/2026-07-31-multi-signal-heading-detection.md.

Run: python scripts/generate_test_documents.py
"""
import sys
from pathlib import Path

REPO_ROOT = Path(__file__).resolve().parent.parent
sys.path.insert(0, str(REPO_ROOT / "backend"))

from docx import Document
from docx.shared import Pt
import fitz

from app.extraction import extract_text
from app.sectioning import split_into_sections

DOCX_DIR = REPO_ROOT / "test-documents" / "docx"
PDF_DIR = REPO_ROOT / "test-documents" / "pdf"

BODY_FONTSIZE = 11
HEADING_FONTSIZE = 16
LINE_GAP = 30
PAGE_MARGIN = 72
# 450 (not a full page's worth, e.g. 720) is deliberate: it caps a page at 13
# lines, so the larger scenarios (C1, SOP: 19-21 lines each) genuinely span
# 2 PDF pages, exercising write_pdf's page-break branch and real multi-page
# TOC/page-number tagging -- while the smaller scenarios (A, B: 12 lines
# each) still fit on one page. A full-page value never exercised the break
# at all, since no scenario in this plan reaches ~22 lines.
PAGE_USABLE_BOTTOM = 450

STRUCTURAL = "structural"
ALL_CAPS = "all_caps"
MIXED = "mixed"
FONT_SIZE = "font_size"
NONE_CONVENTION = "none"


def write_docx(path, sections, convention):
    doc = Document()
    for i, sec in enumerate(sections):
        heading = sec["heading"]
        if heading is not None:
            if convention == STRUCTURAL:
                doc.add_paragraph(heading, style="Heading 1")
            elif convention == ALL_CAPS:
                doc.add_paragraph(heading)
            elif convention == FONT_SIZE:
                p = doc.add_paragraph()
                run = p.add_run(heading)
                run.font.size = Pt(HEADING_FONTSIZE)
            elif convention == MIXED:
                if i % 2 == 0:
                    doc.add_paragraph(heading, style="Heading 1")
                else:
                    doc.add_paragraph(heading)
            elif convention == NONE_CONVENTION:
                doc.add_paragraph(heading)
            else:
                raise ValueError(f"unknown convention: {convention}")
        for body_text in sec["body"]:
            doc.add_paragraph(body_text)
    path.parent.mkdir(parents=True, exist_ok=True)
    doc.save(str(path))


def write_pdf(path, sections, convention):
    pdf = fitz.open()
    page = pdf.new_page()
    state = {"page": page, "y": PAGE_MARGIN, "page_number": 1}
    toc_entries = []

    def emit(text, fontsize):
        if state["y"] > PAGE_USABLE_BOTTOM:
            state["page"] = pdf.new_page()
            state["y"] = PAGE_MARGIN
            state["page_number"] += 1
        state["page"].insert_text((PAGE_MARGIN, state["y"]), text, fontsize=fontsize)
        state["y"] += LINE_GAP
        return state["page_number"]

    for i, sec in enumerate(sections):
        heading = sec["heading"]
        if heading is not None:
            fontsize = HEADING_FONTSIZE if convention == FONT_SIZE else BODY_FONTSIZE
            heading_page = emit(heading, fontsize)
            if convention == STRUCTURAL:
                toc_entries.append([1, heading, heading_page])
            elif convention == MIXED and i % 2 == 0:
                toc_entries.append([1, heading, heading_page])
        for body_text in sec["body"]:
            emit(body_text, BODY_FONTSIZE)

    if toc_entries:
        pdf.set_toc(toc_entries)
    path.parent.mkdir(parents=True, exist_ok=True)
    pdf.save(str(path))
    pdf.close()


def expected_heading_sequence(sections):
    return [sec["heading"] for sec in sections if sec["heading"] is not None]


def validate(path, file_type, sections):
    paragraphs = extract_text(str(path), file_type)
    result_sections = split_into_sections(paragraphs)
    got = [s.heading for s in result_sections]
    expected = expected_heading_sequence(sections)

    if not expected:
        assert all(h.startswith("Paragraph ") for h in got), (
            f"{path.name}: expected no real headings (fallback sections only), got {got}"
        )
        print(f"OK   {path.name}: {len(got)} paragraph-fallback sections, no false headings")
        return

    assert got == expected, f"{path.name}: expected headings {expected}, got {got}"
    print(f"OK   {path.name}: {len(got)} sections, headings match exactly")


def generate_and_validate(name, version, sections, convention):
    docx_path = DOCX_DIR / f"{name}_{version}.docx"
    pdf_path = PDF_DIR / f"{name}_{version}.pdf"
    write_docx(docx_path, sections, convention)
    write_pdf(pdf_path, sections, convention)
    validate(docx_path, "docx", sections)
    validate(pdf_path, "pdf", sections)


# --- Scenario A: numeric-only value changes, no structural change.
# Heading convention: structural (DOCX "Heading 1" style / PDF embedded TOC).

SCENARIO_A_V1 = [
    {"heading": "Effective Date", "body": ["This procedure is effective from 2024-01-15."]},
    {"heading": "Storage Temperature", "body": ["Store the reference standard at -20°C."]},
    {"heading": "Batch Size", "body": ["Manufacture in batches of 1,000 mg per lot."]},
    {"heading": "Reference Standard Weighing", "body": ["Weigh 50 mg of Batch 12 reference standard for the assay."]},
    {"heading": "Container Specification", "body": ["Dispense the solution into a 10 mL amber glass vial."]},
    {"heading": "Calibration Frequency", "body": ["Calibrate the analytical balance every 30 days using a 200 g reference weight."]},
]

SCENARIO_A_V2 = [
    {"heading": "Effective Date", "body": ["This procedure is effective from 2024-03-20."]},
    {"heading": "Storage Temperature", "body": ["Store the reference standard at -70°C."]},
    {"heading": "Batch Size", "body": ["Manufacture in batches of 2,000 mg per lot."]},
    {"heading": "Reference Standard Weighing", "body": ["Weigh 55 mg of Batch 13 reference standard for the assay."]},
    {"heading": "Container Specification", "body": ["Dispense the solution into a 10 L amber glass vial."]},
    {"heading": "Calibration Frequency", "body": ["Calibrate the analytical balance every 30 days using a 200 g reference weight."]},
]


def main():
    generate_and_validate("A", "v1", SCENARIO_A_V1, STRUCTURAL)
    generate_and_validate("A", "v2", SCENARIO_A_V2, STRUCTURAL)


if __name__ == "__main__":
    main()
```

Under the fix, this validates cleanly because both alternation branches are independently evaluated.

C2's original content (`C2_v1.txt`/`C2_v2.txt`) is different in kind from the other 4 scenarios: it's 4 plain paragraphs with **no headings at all** (cleanroom gowning procedure text). Rather than force a heading convention onto content that has none, C2 preserves that — it's a legitimate edge case in its own right (confirms DOCX/PDF extraction+sectioning correctly falls back to one-section-per-paragraph when a real document genuinely has no heading signal of any kind).

Heading text drops the numbering prefix (e.g. "Scope" not "1.0 Scope") and uses no Word style — only an explicit larger font size (`Pt(16)` vs the 11pt body) marks these as headings, isolating the font-size signal added in the heading-detection plan's Task 2 (DOCX) and Task 3 (PDF).

**A verified fixture subtlety you need to know before writing this task's data:** `_pdf_body_baseline_pt` computes the *mode* (most common size) across every text block in the PDF. SOP v2 has exactly 10 headings (all @16pt) and exactly 10 body paragraphs (all @11pt) — an exact count tie. `collections.Counter.most_common(1)` resolves ties by first-insertion order, and since every section's heading block is inserted before its body block, a tie here resolves to 16pt — the *heading* size — which would make the threshold `16 + 2 = 18pt`, so nothing would clear it and the font-size signal would silently never fire for this one file. This was verified directly (not assumed) while writing this plan:
```python
import collections
sizes = [16.0, 11.0] * 10
collections.Counter(sizes).most_common(1)  # -> [(16.0, 10)]
```
The fix: the **PDF fixture only** for `SOP_v2` gets one extra trailing body-only paragraph (`"This marks the end of the procedure."`, `heading=None`) appended after the last section, breaking the tie 11-to-10 in the body's favor. This paragraph has no heading, so it doesn't change `expected_heading_sequence` — validation for this one file passes a slightly extended section list, but still asserts against the same 10 headings. The DOCX fixture for `SOP_v2` does **not** need this — DOCX's baseline is `Normal`-style-or-11.0-hardcoded, not mode-based, so it stays an exact, unmodified translation of `SOP_v2.txt`. `SOP_v1` doesn't need this either on either format — it naturally has 10 body paragraphs (`Materials` has 2) against 9 headings, no tie.
